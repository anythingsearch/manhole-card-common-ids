# マンホールカード取得状況 共通JSON交換仕様（基本ID版 v1）

共同整備・相互運用性検証：**public cardigan / blue25000**

この文書は、両アプリで確認済みの**基本IDによる取得状況交換**を、第三者が実装するための仕様です。版別IDの拡張はまだ本仕様の対象ではありません。

## 1. ファイル構造

- UTF-8で保存したJSONファイル（拡張子 `.json`）。
- 最上位はオブジェクト。必須キーは `format`（文字列、固定値 `manhole-card-collection-exchange`）、`version`（整数、`1`）、`cards`（取得済みの基本ID文字列の配列）。
- 任意キー `exported_at` は、指定する場合はタイムゾーン付きISO 8601日時文字列。
- 空コレクションは `"cards":[]`。配列順序は無関係で、重複した基本IDは1件として扱う。

```json
{
  "format": "manhole-card-collection-exchange",
  "version": 1,
  "exported_at": "2026-10-12T07:00:00+09:00",
  "cards": ["13-225-A001", "31-364-A001"]
}
```

`exported_at` を省略した場合も有効です。

## 2. 基本IDと台帳

基本IDの例：`01-100-A001`、`13-225-A001`、`31-364-A001`、`KH-001-A001`。標準の英大文字と数字の桁数を保持して出力します。

- [基本ID一覧（1,317件）](../data/basic_ids.csv) — IDのみ。
- [5列の照合用CSV](../data/card_reference.csv) — 基本ID・都道府県・カード名・発行弾・カード詳細URL。URLは識別補助のための参考リンクであり、交換時にanythingsearch.infoへのアクセスは不要。

台帳は随時更新されます。**現在の台帳に未掲載のIDを、それだけで一律に不正と判断しないでください。** 自アプリでカードに対応づけられないIDは誤ったカードに割り当てず、取り込めないものとして案内します。

## 3. エクスポート

1. 自アプリ内で取得済みのカードを抽出する。
2. 各アプリ独自の内部IDから共通の基本IDへ対応づける。
3. 重複を除いた基本IDを `cards` に格納して書き出す。
4. 不明なIDを推測で別のカードとして登録しない。

取得日時、ピン色、蓋の訪問状況、位置情報、履歴、利用者情報、同期設定は含めません。

## 4. インポート

1. JSONの構造を検査する。`format`・`version`・`cards` の形式や型が不正なファイル、非対応versionのファイルは**全体を拒否**する。
2. 有効なファイル内の重複IDをまとめ、自アプリのカードと照合する。
3. 対応するカードは**既存取得済みに追加**する。既存記録の削除・全件置換をしない。
4. 同じIDの再取り込みで重複記録を作らず、既存のピン色を変更しない。
5. 対応不能IDは除外し、件数・理由を案内することを推奨する。他の有効なIDの取り込みを妨げない。

画面の名称、ファイルサイズ上限、安全な読み込み方法は各アプリで設計します。大文字小文字混在の受け入れは今回の実機試験で確認した共通要件ではありません。

この交換は**バックアップや双方向自動同期ではありません**。取り込み前のアプリ固有のバックアップを推奨します。

## 5. 旧番号・新番号の例外

| 自治体 | 旧番号 | 新番号 |
| --- | --- | --- |
| 小樽市 | `01-203-A001` | `01-203-A002` |
| 豊富町 | `01-516-A001` | `01-516-A002` |
| 尾張旭市 | `23-226-A001` | `23-226-A002` |

台帳には両番号を収録します。**blue25000のAndroid・iOSアプリは**、同じ自治体のA001とA002を1カードとして扱い、出力時はA002に統一し、どちらの番号を読み込んでも取得済みとし、両方あっても重複しません。

ただし、この統合は第三者アプリへの一律の必須ルールではありません。異なる管理単位を持つアプリを往復すると、出力される基本IDや枚数が変化する場合があります。

## 6. 版別ID（将来拡張）

通常版・特別版・外国語版を細分化する「版別ID」は将来の整備対象です。今回の実機相互交換は**基本ID**で成立しています。版別IDの採番・変換・往復復元を、実装済みの正式要件とはしません。基本IDだけから特定の版を推測して登録しないでください。

## 7. 実機で確認済みの交換

- blue25000 Android → public cardigan Android
- blue25000 iOS → public cardigan Android
- public cardigan Android → blue25000 Android
- public cardigan Android → blue25000 iOS

追加取得・再取り込みでの重複なし・既存のピン色保持を確認しました。すべての将来の端末や実装での動作まで保証するものではありません。
